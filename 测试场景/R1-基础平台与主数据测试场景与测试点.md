## 一、使用说明

### 1.1 文档定位

本文档将验收标准（AC）逐条拆解为**测试点（Test Point）**，每个测试点描述一个可独立验证的场景，包含前置条件、操作输入与预期断言，可直接映射为一个单元测试方法。

### 1.2 编号规则

```
TP-R1-{功能点编号}-{两位序号}
```

与验收标准通过"关联 AC"列追溯，例如 `TP-R1-1.3.1-04` 对应 `AC-R1-1.3.1-03`。

### 1.3 测试层级说明

| 层级 | 含义 | 生成单元测试 |
|---|---|---|
| U | 单元测试：Service 层业务逻辑，依赖可 Mock | ✅ 可直接生成 JUnit 测试方法 |
| I | 集成测试：涉及跨模块、数据库、文件、前端交互 | ⚠️ 建议生成集成测试或转为服务层验证，不由单元测试直接覆盖 |

### 1.4 命名规范（生成代码时使用）

| 对象 | 规范 | 示例 |
|---|---|---|
| 测试类 | `{被测类}Test` | `SkuServiceTest`、`AuthServiceTest` |
| 正向方法 | `should{预期结果}When{条件}` | `shouldCreateSkuWhenDataValid` |
| 异常方法 | `shouldThrow{异常}When{条件}` | `shouldThrowExceptionWhenSkuCodeExists` |
| 边界方法 | `should{预期}When{边界条件}` | `shouldResetSerialWhenNextDay` |

### 1.5 方法内部结构（Given / When / Then）

每个测试点转为单元测试方法时按三段式组织：

| 段落 | 内容 | 对应测试点列 |
|---|---|---|
| Given | 数据准备、Mock 依赖返回值 | 「前置条件与操作」中的前置部分 |
| When | 调用被测方法 | 「前置条件与操作」中的操作部分 |
| Then | 断言返回值、状态变更、异常类型与消息、Mock 调用次数 | 「预期结果（断言点）」 |

### 1.6 依赖 Mock 建议

| 依赖 | 处理方式 |
|---|---|
| Mapper / Repository | Mock（Mockito），不连真实数据库 |
| 缓存（编码生成、字典缓存） | Mock 或嵌入式缓存 |
| 文件导入导出 | 构造内存中的 MockMultipartFile / 临时文件 |
| 密码加密 | Mock 加密组件，断言密文不等于明文 |
| 当前登录用户 | Mock 上下文，构造用户与角色权限 |
