## 一、架构总览

```
                    ┌──────────────┐
   PDA/PC ──HTTP──▶ │  wms-gateway │  路由 + JWT 校验 + 黑名单
                    └──────┬───────┘
        ┌──────────────────┼───────────────────────┐
        ▼                  ▼                        ▼
   ┌──────────┐      ┌────────────┐         ┌────────────┐
   │ wms-auth │      │ wms-system │         │ wms-base   │
   └──────────┘      └────────────┘         └────────────┘
                          │ Feign                │ Feign（查 SKU/库位/仓库）
                          ▼                      ▼
                   ┌──────────────┐      ┌──────────────┐
   wms-inbound ───▶│ wms-inventory │◀─── │ wms-inbound  │
   (入库流程)       │  (库存核心)  │      (查主数据)
                   └──────────────┘
```

**新增服务**：
- `wms-inbound`（入库管理）：预约单 / 验收 / 质检 / 上架任务
- `wms-inventory`（库存核心）：库存 / 流水 / 调整 / 预警
- `wms-api-inventory`（Feign 接口）：`wms-inventory` 暴露给 `wms-inbound` 调用的内部接口

| 库存 | `inv_adjust` | 库存调整单（审批流） |

**关键约束**：
- `inv_stock.uk_stock = (sku_id, warehouse_id, location_id, batch_no, deleted)` —— 同一库位同批次唯一
- `inbound_order.uk_inbound_no` / `putaway_task.uk_task_no` / `inv_transaction.uk_transaction_no` / `inv_adjust.uk_adjust_no` 唯一
- `inv_stock.version` 乐观锁，防止并发上架超卖

## 四、关键业务流程

### 4.1 入库单状态机

```
DRAFT ──确认──▶ CONFIRMED ──到货──▶ ARRIVED ──提交质检──▶ PENDING_QC
                                                  │
              COMPLETED ◀──完成── PUTTING_AWAY ◀──┘ (质检通过)
   任意状态 ──取消──▶ CANCELLED（终态）
```

**状态校验**（`InboundOrder.Status` 枚举 + `canTransition` 方法）：
- DRAFT 可编辑、可删除
- CONFIRMED 可到货、可取消，不可删除
- ARRIVED 必须提交质检，不可修改明细
- PENDING_QC 质检通过后进入 PUTTING_AWAY
- PUTTING_AWAY 上架完成后进入 COMPLETED
- CANCELLED / COMPLETED 终态

### 4.2 上架增加库存（跨服务事务）

```
wms-inbound 上架确认
   1. 校验上架数量 ≤ 待上架数量
   2. 校验库位状态（非 LOCKED / MAINTENANCE）
   3. 调用 wms-inventory Feign: increaseStock(skuId, locationId, batchNo, qty, relatedNo)
   4. wms-inventory 内：
      - @Transactional + 乐观锁更新 inv_stock（可用+总库存）
      - 生成 inv_transaction 流水（INBOUND）
   5. 回写 inbound_item.putaway_qty，全部上架完成后订单置 COMPLETED
```

**一致性策略**：最终一致。上架确认以 inbound 为主，库存增加失败则回滚 inbound 事务并提示。

### 4.3 库存调整审批

```
DRAFT ──提交──▶ PENDING（待审批）
PENDING ──通过──▶ APPROVED  → 调用 increase/decrease 调整库存 + 生成 ADJUST 流水
PENDING ──驳回──▶ REJECTED
```

## 五、库存核心 API（wms-api-inventory）

| 接口 | 方法 | HTTP | 路径 | 调用方 |
|---|---|---|---|---|
| `StockFeignClient.increase` | POST | `/internal/stock/increase` | wms-inbound |
| `StockFeignClient.decrease` | POST | `/internal/stock/decrease` | wms-outbound(R3) |
| `StockFeignClient.lock` | POST | `/internal/stock/lock` | wms-outbound(R3) |
| `StockFeignClient.unlock` | POST | `/internal/stock/unlock` | wms-outbound(R3) |
| `StockFeignClient.queryByLocation` | GET | `/internal/stock/location/{id}` | wms-base |

**DTO**：`StockChangeDTO(skuId, locationId, batchNo, quantity, relatedNo, operator, remark)`

## 七、技术选型与复用

- **统一响应 / 异常 / 鉴权**：复用 `wms-common-*`（R1 已落地）
- **编码规则**：入库单号 `IN+日期+3位流水`，复用 `CodeRuleFeignClient`
- **操作日志**：`@OperationLog` 注解（wms-common-log）
- **乐观锁**：`inv_stock.version` + MyBatis-Plus `@Version`
- **库存流水不可改**：`inv_transaction` 仅 INSERT
