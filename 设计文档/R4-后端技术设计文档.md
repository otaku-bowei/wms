## 一、架构总览

```
            ┌──────────────┐  extend  ┌──────────────┐
            │ wms-inventory│─────────▶│  AdjustService│ 盘点差异复用调整单
            │ (盘点扩展)    │         │  (审批增减库存)│
            └──────────────┘         └──────────────┘
                     ▲
                     │ 复用 R2 调整能力
   PDA/PC ─ HTTP ──▶ ┌──────────────┐   Feign.increase  ┌──────────────┐
                     │  wms-return  │ ────────────────▶ │ wms-inventory │
                     │  (退货)      │                   │  (库存核心)  │
                     └──────────────┘                   └──────────────┘

   PC ─ HTTP ──▶ ┌──────────────┐  读共享库 inv_stock / *order / count_item
                 │  wms-report  │  （KPI 看板 + 五类业务报表，只读聚合）
                 └──────────────┘
```

**新增/扩展服务**：
- `wms-inventory`（扩展）：新增盘点模块（盘点单/明细 + `CountService`，差异生成复用 R2 的 `AdjustService`）
- `wms-return`（新增，端口 9205）：退货收货 / 质检分级 / 重新上架（A 级调 `StockFeignClient.increase` 回写库存）
- `wms-report`（新增，端口 9206）：KPI 看板 + 入库/出库/库存/退货/盘点五类报表（读共享库聚合）

## 三、关键业务流程

### 3.1 盘点（复用 R2 调整单）

```
createCountOrder → 按系统库存回填 systemQty（PENDING）
recordCount(itemId, countedQty) → 回写 diffQty、置 COUNTED，订单转 COUNTING
generateDiff(countId) → 对差异明细生成 ADJ(CHECK) 调整单并审批
                      → 调 StockService.increase/decrease 回写库存
                      → 明细 ADJUSTED、订单 COMPLETED
```

### 3.2 退货（状态机 + 重新上架）

```
CREATED ──receive()──▶ RECEIVED ──inspect()──▶ INSPECTED ──reshelve()──▶ RESHELVED → CLOSED
  收货(实收=计划)        质检分级(A/B/C)         A 级调 increase 回写库存
```

- A 级：直接上架 → `StockFeignClient.increase(sku, location, receivedQty)`
- B 级（翻新）/ C 级（不良品）：仅记录，不回写可用库存（不良品单独处理）

### 3.3 报表

- **KPI 看板** `GET /api/v1/report/kpi`：库存准确率、库存总量/可用量、今日入/出库单量、待出库单量
- **出库报表** `GET /api/v1/report/outbound`：按状态分布
- **入库报表** `GET /api/v1/report/inbound`：按状态分布
- **库存报表** `GET /api/v1/report/inventory`：按仓库汇总总量/可用量
- **退货报表** `GET /api/v1/report/return`：按状态分布
- **盘点报表** `GET /api/v1/report/count`：账实准确率

## 四、核心 API

| 接口 | HTTP | 路径 | 说明 |
|---|---|---|---|
| 创建盘点单 | POST | `/api/v1/inventory/count` | 按系统库存回填 |
| 录入实盘 | PUT | `/api/v1/inventory/count/items/{id}/record` | countedQty |
| 生成差异 | POST | `/api/v1/inventory/count/{id}/generate` | 复用调整单 |
| 创建退货单 | POST | `/api/v1/return` | CREATED |
| 退货收货 | PUT | `/api/v1/return/{id}/receive` | RECEIVED |
| 质检分级 | PUT | `/api/v1/return/{id}/inspect` | INSPECTED |
| 重新上架 | PUT | `/api/v1/return/{id}/reshelve` | A 级回写库存 |
| KPI 看板 | GET | `/api/v1/report/kpi` | 实时指标 |
| 业务报表 | GET | `/api/v1/report/{outbound\|inbound\|inventory\|return\|count}` | 多维聚合 |

## 七、与 R1–R3 的复用

- 盘点差异：复用 R2 `AdjustService.createAdjust` + `audit`（已放宽允许 DRAFT 直接审批）
- 退货上架：复用 `StockFeignClient.increase`（R2 库存核心）
- 报表：读取 R2–R3 已落库的业务表，`deleted` 逻辑删除自动过滤

> 本设计随代码生成持续同步。
