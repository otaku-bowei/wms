## 一、概述

### 1.1 设计目标

基于接口文档与数据库设计，完成 R1 阶段后端工程的技术落地方案：微服务划分、工程结构、分层职责、公共能力设计、关键流程实现方案与部署架构。

### 1.2 设计原则

| 原则 | 说明 |
|---|---|
| 服务适度拆分 | 按领域边界拆分，避免粒度过细导致运维成本过高 |
| 公共能力下沉 | 统一响应、异常、鉴权、日志、缓存等沉淀到公共模块 |
| 接口与实现分离 | Feign 接口集中在 `wms-api` 模块，避免服务间循环依赖 |
| 面向后续演进 | R2-R5 新增服务可平滑接入，不改现有骨架 |
| 约定优于配置 | 统一命名、分层、包结构，降低协作成本 |

### 1.3 非目标

- 不包含前端设计与实现
- 不包含 R2 及以后版本的详细设计（仅在演进章节给出规划）

### 3.3 服务调用关系

```
wms-auth   ──Feign──▶ wms-system  查询用户、角色、权限树
wms-base   ──Feign──▶ wms-system  查询字典枚举（可选）、当前用户信息（审计字段）
wms-base   ──Feign──▶ wms-auth    权限校验（可选，通常由 Gateway 完成）

所有服务 ──▶ Nacos（注册/配置）、Redis、MySQL
```

**注意**：`wms-auth` 与 `wms-system` 之间为单向依赖，禁止反向调用；共用 Feign 客户端模块 `wms-api-system`。

### 4.3 分层职责约束

| 层 | 职责 | 禁止事项 |
|---|---|---|
| Controller | 参数校验、调用 Service、组装 VO | 禁止写业务逻辑、禁止直接调 Mapper |
| Service | 业务编排、事务控制、领域规则 | 禁止直接返回 Entity 给前端 |

## 五、核心服务设计

### 5.1 网关服务 wms-gateway

**职责**：

| 能力 | 实现 |
|---|---|
| 路由转发 | Nacos 服务发现 + 路径前缀路由 |
| JWT 校验 | 全局过滤器校验签名与有效期 |
| Token 黑名单 | 登出后校验 Redis 黑名单，命中则拒绝 |
| 用户信息透传 | 解析 Token 后写入请求头 `X-User-Id`、`X-User-Name`、`X-Role-Code`、`X-Warehouse-Id` |
| 限流 | Sentinel / RequestRateLimiter（按 IP + 路径） |
| 跨域 | 统一 CORS 配置 |
| 链路追踪 | 生成/透传 traceId |

**路由配置**：

| 路由 ID | 断言路径 | 目标服务 | 是否鉴权 |
|---|---|---|---|
| auth | `/api/v1/auth/login`、`/api/v1/auth/refresh` | wms-auth | 否（白名单） |
| auth-api | `/api/v1/auth/**`（其余） | wms-auth | 是 |
| system | `/api/v1/users/**`、`/api/v1/roles/**`、`/api/v1/permissions/**`、`/api/v1/logs/**`、`/api/v1/config/**` | wms-system | 是 |
| base | `/api/v1/skus/**`、`/api/v1/warehouses/**`、`/api/v1/zones/**`、`/api/v1/locations/**`、`/api/v1/suppliers/**` | wms-base | 是 |

**鉴权过滤器流程**：

```
接收请求
  ↓
是否为白名单路径？── 是 ──▶ 放行
  ↓ 否
提取 Header: Authorization = Bearer {token}
  ↓ 缺失或不合法
返回 401 { code: 401 }
  ↓ 存在
校验 JWT 签名与过期时间 ── 失败 ──▶ 401
  ↓ 通过
查询 Redis 黑名单 auth:token:blacklist:{jti} ── 命中 ──▶ 401
  ↓ 未命中
解析 userId/username/roleCode/warehouseId 写入请求头，透传给下游服务
  ↓
放行
```

### 5.2 认证服务 wms-auth

**职责**：登录、登出、修改密码、刷新 Token、查询当前用户与菜单权限。

**核心类**：

| 类 | 职责 |
|---|---|
| `AuthController` | 暴露 `/auth` 接口 |
| `AuthService` | 登录业务编排（校验→生成 Token→记录日志） |
| `LoginGuard` | 防暴力破解：失败计数、账户锁定判定 |
| `TokenService` | JWT 生成/刷新/黑名单管理 |
| `MenuService` | 组装菜单树与按钮权限集合 |
| `SystemUserClient` | Feign 调用 system 服务查询用户与权限 |

**登录流程**：

```
1. 参数校验（@Valid）
2. Feign 查询用户信息（system: /internal/users/by-username/{username}）
   ├─ 不存在 → 记录失败日志，抛出 10001
   └─ 存在
3. LoginGuard 校验账户状态
   ├─ Redis 存在锁 key → 抛出 10003（账户已锁定）
   ├─ 用户 status=0 → 抛出 10002（账户已停用）
   └─ 通过
4. BCrypt 校验密码
   ├─ 失败 → Redis 计数 login:fail:{username} +1（TTL 30min）
   │        达到阈值 → 写入 login:lock:{username}（TTL 30min）
   │        记录登录日志 FAIL → 抛出 10001（返回剩余次数）
   └─ 成功 → 清除失败计数
5. 生成 JWT（jti + userId + username + roleCode + warehouseId，有效期 8h）
6. 更新最后登录时间/IP（Feign 调 system）
7. 记录登录日志 SUCCESS
8. 返回 token、userInfo、forceChangePassword 标记
```

**JWT 载荷设计**：

| 字段 | 说明 |
|---|---|
| jti | Token 唯一 ID，用于黑名单 |
| sub | userId |
| username | 用户名 |
| roleCode | 角色编码 |
| warehouseId | 所属仓库（数据权限隔离） |
| iat / exp | 签发/过期时间（8 小时） |

**菜单权限查询**：

```
GET /auth/menus
1. 从安全上下文取 userId / roleCode
2. 查 Redis: auth:perms:{userId}
   ├─ 命中 → 直接返回
   └─ 未命中 → Feign 调 system 查 permission 列表，写 Redis（TTL 30min）
3. 组装菜单树（MENU 类型，树形展开）+ 按钮权限集合（permissionCode 列表）
4. 返回
```

### 5.3 系统服务 wms-system

**职责**：覆盖 `sys_` 域 10 张表与相关 22 个接口。

**模块划分**：

| 模块 | 接口 | 核心类 |
|---|---|---|
| 用户管理 | 7 | `UserController`、`UserService`、`UserConverter` |
| 角色权限 | 6 | `RoleController`、`RoleService`、`PermissionService` |
| 日志中心 | 2 | `LogController`、`OperationLogService`、`LoginLogService` |
| 字典配置 | 7 | `DictController`、`CodeRuleService`、`ConfigService` |
| 内部接口 | Feign | `InternalUserController`（供 auth 调用） |

**用户管理关键点**：

| 场景 | 实现方案 |
|---|---|
| 创建用户 | 生成初始密码 BCrypt 加密；返回明文初始密码（仅本次）；记录操作日志 |
| 用户名唯一 | DB 唯一索引 + 创建前 `existsByUsername` 前置校验（友好提示） |
| 停用用户 | 更新 status；同时清理 Redis 权限缓存 `auth:perms:{userId}`（即时生效） |
| 重置密码 | 重置为初始密码 + 置 `force_change_password=1` |
| 用户列表 | 关联查询角色名与仓库名（单表查后再批量补全，避免复杂 JOIN） |

**角色权限关键点**：

| 场景 | 实现方案 |
|---|---|
| 权限树 | `sys_permission` 全量查（缓存），内存组装树形结构 |
| 配置权限 | 先删后插 `sys_role_permission`（事务保证） |
| 权限生效 | 配置变更 → 清理该角色下所有用户的 `auth:perms:{userId}` 缓存 |
| 内置角色保护 | `builtin=1` 时拒绝删除（Service 层校验） |

### 5.4 基础数据服务 wms-base

**职责**：覆盖 `base_` 域 7 张表与相关 30 个接口。

**模块划分**：

| 模块 | 接口 | 核心类 |
|---|---|---|
| SKU | 9 | `SkuController`、`SkuService`、`SkuImportListener`、`SkuExportService` |
| 仓库/区域 | 9 | `WarehouseController`、`WarehouseService`、`ZoneService` |
| 库位 | 7 | `LocationController`、`LocationService`、`LocationLayoutService` |
| 供应商 | 5 | `SupplierController`、`SupplierService` |

**SKU 批量导入设计**（重点）：

```
POST /skus/import
1. 校验文件（格式/大小/行数）
2. EasyExcel 同步读（SkuImportListener）
   ├─ invoke(): 逐行解析 → 校验 → 加入批次列表
   └─ doAfterAllAnalysed(): 批量落库
3. 分批（500 条/批）入库，单条失败不影响整批（try-catch 逐条）
4. 收集失败行：{row, data, reason}
5. 存在失败行 → 生成失败明细 Excel 上传 OSS，返回下载 URL
6. 返回 {totalCount, successCount, failCount, failFileUrl, errors[]}
```

**一键多码设计**：

| 场景 | 实现 |
|---|---|
| 创建 | 主表插入 SKU 后，批量插入 `base_sku_barcode` |
| 唯一性 | 依赖 `uk_barcode`；Service 前置查 `existsByBarcode` 给出友好提示 |
| 反查 | `location_code`/按条码查 SKU → JOIN 子表或先查 barcode 再查 sku |

**库位批量创建设计**：

| 场景 | 实现 |
|---|---|
| 笛卡尔积生成 | 内存按 货架×层×列×位 生成编码列表 |
| 幂等去重 | 先查已存在编码集合，差集后再插入 |
| 数量限制 | 单次 ≤ 5000，Service 层拦截 |
| 数据量保障 | 分批插入（500/批），单事务提交；失败整体回滚 |

**2D 平面图设计**：

```
GET /locations/layout?warehouseId=&zoneId=&shelf=
1. 查询该仓库/区域下所有库位（限定货架可选）
2. 按 (shelf, layer, column) 组装矩阵 Map<(shelf,layer,column), LocationVO>
3. 计算每个单元格的 colorLevel：
   ├─ LOCKED / MAINTENANCE → GRAY
   ├─ OCCUPIED 且 used/max ≥ 95% → RED（已满）
   ├─ OCCUPIED 且 used/max > 0  → YELLOW（部分占用）
   └─ FREE → GREEN（空闲）
4. 返回 cells[]（含坐标、状态、使用率、颜色等级）
```

## 六、公共能力设计

### 6.1 统一响应

```java
public record R<T>(int code, String message, T data, long timestamp, String traceId) {
    public static <T> R<T> ok(T data) { ... }
    public static <T> R<T> fail(int code, String message) { ... }
}
```

- 所有 Controller 返回 `R<T>`
- `timestamp`、`traceId` 由 `ResponseBodyAdvice` 自动填充（traceId 取自 MDC）
- 分页统一使用 `PageResult<T>`（`list/total/pageNum/pageSize/pages`）

### 6.2 错误码体系

```java
public interface ResultCode {
    int SUCCESS = 0;
    int PARAM_ERROR = 400;
    int UNAUTHORIZED = 401;
    int FORBIDDEN = 403;
    int NOT_FOUND = 404;
    int SYSTEM_ERROR = 500;
}

public interface BizCode {
    int USER_CREDENTIAL_ERROR = 10001;
```

### 6.3 全局异常处理

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(BizException.class)      // 业务异常 → code + message
    @ExceptionHandler(MethodArgumentNotValidException.class)  // 参数校验 → 400 + 首个错误信息
    @ExceptionHandler(AccessDeniedException.class)            // 无权限 → 403
    @ExceptionHandler(Exception.class)         // 兜底 → 500 + 通用提示 + 日志记录 traceId
}
```

**要点**：兜底异常不向客户端暴露堆栈信息，仅返回 `traceId` 供排查（对应 AC-R1-1.1.4-02）。

### 6.4 RBAC 鉴权实现

**后端鉴权注解**：

```java
@RequirePermission("sku:create")   // AOP 切面 + Spring Security @PreAuthorize 双保险
@PostMapping("/skus")
public R<Long> create(@Valid @RequestBody SkuCreateDTO dto) { ... }
```

**鉴权流程**：

```
请求进入服务
  ↓
AuthInterceptor / Spring Security Filter 从请求头取 userId/roleCode
  ↓
构建 UserPrincipal，写入 SecurityContextHolder + ThreadLocal（UserContext）
  ↓
@RequirePermission 切面获取当前用户权限集合（Redis 缓存）
  ↓
是否包含所需 permissionCode？
 ├─ 是 → 放行
 └─ 否 → 抛出 AccessDeniedException → 全局异常处理返回 403
```

### 6.5 数据权限（仓库隔离）

| 角色 | 数据范围 |
|---|---|
| 系统管理员 | 全部仓库 |
| 库管主管 / 仓库管理员 / 拣货员 / 复核员 | 仅自身 `warehouseId` |

**实现**：MyBatis-Plus 数据权限插件，自动在 SQL 追加 `warehouse_id = ?` 条件；系统管理员跳过。

### 6.6 操作日志（AOP）

```java
@OperationLog(module = Module.SKU, type = OperationType.CREATE, description = "创建SKU")
@PostMapping
public R<Long> create(@RequestBody SkuCreateDTO dto) { ... }
```

| 要素 | 方案 |
|---|---|
| 采集 | AOP 环绕通知，记录操作前后参数与结果 |
| 脱敏 | 敏感字段（password、oldPassword）使用 `@Sensitive` 注解标记，序列化为 `******` |
| 异步 | 切面内发布事件，`@Async` + 线程池异步落库，避免拖慢主流程 |
| 归档 | 日志表按 `operate_time` 保留 180 天（参数 `log.retention.days`，XXL-Job 定时清理） |

### 6.7 Redis 缓存设计

**Key 规范**：`{系统}:{模块}:{业务}:{标识}`

| Key | 类型 | TTL | 说明 |
|---|---|---|---|
| `wms:auth:perms:{userId}` | Hash/JSON | 30 min | 用户权限集合 |
| `wms:auth:token:blacklist:{jti}` | String | Token 剩余有效期 | 登出黑名单 |
| `wms:auth:login:fail:{username}` | String(计数) | 30 min | 登录失败次数 |
| `wms:auth:login:lock:{username}` | String | 30 min | 账户锁定 |
| `wms:sys:dict:{dictType}` | JSON | 60 min | 字典项缓存 |
| `wms:sys:config:{paramKey}` | String | 60 min | 系统参数 |
| `wms:seq:{ruleType}:{date}` | String(计数) | 自然过期 | 流水号自增 |
| `wms:lock:{bizKey}` | String | 按业务 | Redisson 分布式锁 |
| `wms:idempotent:{key}` | String | 5 min | 幂等去重 |

**一致性策略**：
- 采用 **Cache-Aside**：读时先查缓存，未命中回源；写时先更新 DB 再删除缓存
- 字典/参数/权限更新后，通过 Spring Event 发布缓存失效事件，清理本地 + Redis

### 6.8 编码生成器

**需求**：
- 规则驱动（前缀 + 日期格式 + 流水号位数 + 重置方式）
- 并发安全、高性能、跨服务复用

**实现**：

```
GET /config/next-code/{ruleType}
1. 查 sys_code_rule（本地缓存）
2. Redis INCR（原子自增）：wms:seq:{ruleType}:{datePart}
3. 首次自增后设置过期时间（按重置方式：DAY→次日凌晨，MONTH→次月，NEVER→不过期）
4. 格式化流水号（LPAD 补零到 serialLength）
5. 拼接：prefix + datePart + serial
6. 异步持久化 current_seq 到 DB（兜底，Redis 失效时可恢复）
```

### 6.9 Excel 导入导出

| 环节 | 方案 |
|---|---|
| 导出 | EasyExcel 流式写 + `@ExcelProperty` 注解定义列名；大数据量分批查库写 |
| 导入 | EasyExcel 监听器逐行解析 + `AnalysisEventListener`；分批处理避免 OOM |
| 模板下载 | 静态资源 + 动态列表头（Dictionary 动态下拉可选） |
| 失败明细 | 生成含有_ERR 列的错误 Excel，上传 OSS 后返回 URL |

### 6.10 幂等与分布式锁

| 场景 | 方案 |
|---|---|
| 创建接口重复提交 | Header `Idempotency-Key` + Redis SETNX（5 分钟窗口） |
| 批量创建库位并发 | Redisson 分布式锁 `lock:location:batch:{zoneId}` |
| 编码生成并发 | Redis INCR 原子操作 |
| 角色权限并发配置 | 乐观锁（`@Version`）+ 重试 |

### 6.11 分页统一

使用 MyBatis-Plus `Page<T>` + 自定义分页插件，Controller 入参统一继承 `PageQuery`（pageNum/pageSize，默认 1/20，单次最大 100）。

### 7.1 ORM 约定

| 约定 | 说明 |
|---|---|
| 实体 | `@TableName` 显式指定表名；字段与列名下划线自动映射 |

### 7.3 事务规范

| 原则 | 说明 |
|---|---|
| 标注位置 | `@Transactional` 标注在 Service 实现方法 |
| 传播行为 | 默认 `REQUIRED`；日志、消息等辅助操作使用 `REQUIRES_NEW` 或异步 |

## 九、安全设计

| 维度 | 措施 |
|---|---|
| 密码存储 | BCrypt（`BCryptPasswordEncoder`，strength 10），禁止明文/MD5 |
| 传输安全 | 全站 HTTPS；JWT 走 Authorization Header |
| Token 失效 | 登出写入黑名单；修改密码后旧 Token 失效 |
| 暴力破解 | Redis 失败计数 + 30 分钟锁定（可配置） |
| 越权防护 | 菜单 + 按钮双级鉴权；数据权限自动追加仓库条件 |
| 参数校验 | `@Valid` + 自定义注解；前后端双重校验 |
| SQL 注入 | 全部使用预编译参数绑定（`#{}`），禁止 `${}` 拼接用户输入 |
| 日志脱敏 | 密码类字段统一 `******` |
| 接口幂等 | `Idempotency-Key` + Redis SETNX |
| XSS | 统一请求参数过滤 + 响应转义 |

## 十四、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 微服务联调成本高 | 进度风险 | R1 仅 4 个服务；本地 Docker Compose 一键起全环境 |
| Redis 不可用时登录阻塞 | 可用性 | 本地缓存兜底 + 快速失败告警 |

| EasyExcel 大文件 OOM | 稳定性 | 行数上限 5000 + 分批入库 + JVM 调优 |
| 逻辑删除导致唯一索引冲突 | 数据异常 | 唯一索引包含 `deleted` 字段（已在建表脚本处理） |
