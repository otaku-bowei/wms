## 一、设计约定

### 1.1 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 数据库 | 小写下划线 | `wms` |
| 表 | `{域前缀}_{业务名}`，系统域 `sys_`、基础数据域 `base_` | `sys_user`、`base_sku` |
| 字段 | 小写下划线 | `sku_code`、`create_time` |
| 主键 | 统一 `id`，`BIGINT UNSIGNED AUTO_INCREMENT` | `id` |
| 唯一索引 | `uk_{字段缩写}` | `uk_sku_code` |
| 普通索引 | `idx_{字段缩写}` | `idx_status` |

### 1.2 通用字段

业务主数据表统一包含以下审计字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `create_by` | VARCHAR(50) | 创建人 |
| `create_time` | DATETIME | 创建时间，默认 `CURRENT_TIMESTAMP` |
| `update_by` | VARCHAR(50) | 修改人 |
| `update_time` | DATETIME | 修改时间，`ON UPDATE CURRENT_TIMESTAMP` |
| `deleted` | TINYINT | 逻辑删除：0 未删除 / 1 已删除，默认 0 |

### 1.3 其他约定

| 项 | 约定 |
|---|---|
| 存储引擎 | InnoDB |
| 字符集 | `utf8mb4`，排序规则 `utf8mb4_general_ci` |
| 删除策略 | **逻辑删除**（`deleted` 字段），不使用物理删除 |
| 金额/重量 | `DECIMAL(10,2)`；体积 `DECIMAL(10,3)` |
| 状态字段 | 使用 TINYINT（1 启用 / 0 停用）或 VARCHAR 枚举（多状态） |
| 密码存储 | BCrypt 密文，绝不明文 |
| 日志表 | 数据量大，按时间建索引，定期归档（默认保留 180 天） |
| 外键 | 不使用物理外键，仅在应用层保证引用完整性，便于分库扩展 |

| email | VARCHAR(100) | 是 | NULL | 邮箱 |

| fail_count | INT | 否 | 0 | 连续登录失败次数 |
| lock_time | DATETIME | 是 | NULL | 账户锁定时间 |

| update_by | VARCHAR(50) | 是 | NULL | 修改人 |
| update_time | DATETIME | 否 | CURRENT_TIMESTAMP | 修改时间，自动更新 |

## 七、数据量估算与性能设计

| 表 | 预估数据量 | 说明 |
|---|---|---|
| sys_user | 数百 | 小表 |
| base_sku | 10 万级 | 分页查询，注意 `sku_name` 模糊查询性能 |
| base_sku_barcode | 10~15 万 | 与 SKU 约 1:1.2 |
| base_location | 单仓 1~2 万 | 按仓库/区域索引查询 |
| sys_operation_log | 千万级 | **大表**，按月归档 |
| sys_login_log | 百万级 | 定期归档 |

**优化建议**：
1. 日志表按月分区或分表，保留 180 天
2. SKU 名称模糊查询量大时引入 Elasticsearch
3. 字典、编码规则、系统参数缓存至 Redis，减少 DB 访问
4. 编码生成用 Redis 原子自增，`sys_code_rule.current_seq` 仅作持久化
