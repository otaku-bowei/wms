## 一、文档说明

### 1.1 文档定位

本文档从**产品与业务视角**定义 R1 各功能点的验收标准（AC），描述"系统在业务上应表现出什么行为"，供产品验收与测试用例编写使用。

**本文档不描述技术实现细节**（接口地址、错误码、Token 机制、数据库存储方式等），技术实现以接口文档为准。

### 1.2 编号规则

```
AC-R1-{功能点编号}-{两位序号}
```

与《R1 功能点文档》的功能点编号一一对应，支持双向追溯。

示例：`AC-R1-1.3.1-01` 表示功能点 1.3.1（SKU 创建）的第 1 条验收标准。

### 1.3 如何使用本文档生成测试用例

| 规则 | 说明 |
|---|---|
| 规则 1 | 每条 AC 至少对应 1 条测试用例，测试用例编号建议 `TC-R1-{功能点编号}-{序号}`，并在用例中标注"来源 AC 编号" |
| 规则 2 | AC 描述中含"应提示 / 应拒绝 / 不允许 / 不可"的，需同时编写**正向用例**与**反向（异常）用例** |
| 规则 3 | 涉及状态变更的 AC（启用/停用/锁定/解锁），需覆盖变更前后两个状态及变更后的业务影响 |
| 规则 4 | 涉及列表查询的 AC，需覆盖"有数据"与"无数据"两种场景 |
| 规则 5 | 涉及唯一性校验的 AC，需覆盖"已存在"与"不存在"两种场景 |
| 规则 6 | 标注"需在 R2/R4/R5 交叉验证"的 AC，在对应版本回归时重新执行 |

### 1.4 优先级定义

| 优先级 | 含义 | 验收要求 |
|---|---|---|
| P0 | 核心主流程与关键业务规则，不满足则阻塞上线 | 100% 满足 |
| P1 | 重要功能与常规校验 | ≥ 95% 满足 |
| P2 | 进阶/增强功能 | ≥ 90% 满足 |
